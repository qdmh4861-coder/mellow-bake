## 수정 완료

### 1. 준비 중 안내에서 멈추던 구매 연결

- 모든 상세페이지의 바로 구매 버튼은 기존 `addToCart`를 재사용해 해당 수량을 담고 `/cart`로 이동한다. 기존 카드·버튼·이미지 디자인은 그대로다.
- 장바구니 주문하기는 체크된 상품만 세션에 담아 기존 `/mypage/orders/detail?orderId=portfolio-…` 화면으로 전달한다.
- 해당 경우에만 제목을 **시연용 주문 확인**으로 표시하고, 실제 주문·결제·배송 요청이 없다는 안내를 기존 안내문 스타일로 표시한다.
- 금액은 상품 합계다. 배송비·할인·실제 결제 금액으로 오인하지 않도록 **상품 기준 예상 금액**으로 표시한다.
- 결제·개인정보 입력 폼은 만들지 않았으며, 실제 주문 데이터나 장바구니 상품을 삭제하지 않는다. 세션에 제품 정보만 저장하므로 새로고침해도 확인할 수 있고 다른 브라우저와 동기화되지는 않는다.
- 기존 주문 상세의 구성·스타일을 재사용했다. 새 주문/결제 페이지를 생성하지 않았다.

### 2. 로그인 후 원래 요청 화면으로 돌아오지 않던 연결

- 보호 페이지에서 로그인으로 이동할 때 `next`에 기존 내부 경로를 전달한다.
- 로그인 후 같은 출처의 보호 경로만 허용하고, 외부 URL·잘못된 URL은 마이페이지로 대체한다.
- 직접 로그인한 경우의 기본 목적지는 기존대로 마이페이지다.

### 3. 회원 메뉴의 마우스 클릭 충돌

- 마우스가 올라와 이미 열린 회원 메뉴를 클릭하면 토글 때문에 즉시 닫히던 문제를 확인했다.
- 마우스 클릭은 열린 상태를 유지하고, 터치·키보드의 토글 동작과 기존 바깥 클릭/ESC 닫기는 유지했다. 아이콘·위치·색상·드롭다운 CSS는 변경하지 않았다.

### 4. 최초 방문 시 상세 URL이 HOME으로 바뀌던 문제

- 기존 로딩 종료 코드가 HOME이 아닌 경로를 `/`로 바꾸고 있었다.
- 해당 강제 이동만 제거했다. 기존 애니메이션·시간·모양은 유지한다.

### 5. 이미지형 추천 상품의 연결 누락

- 소금빵과 시나몬롤의 하단 추천 상품 시안에 카드별 투명 링크를 연결했다.
- 시안 자체와 상품 설명·가격·프레임은 변경하지 않았다. 키보드용 링크 이름을 제공했다.
- 기존 완성 상세 3개의 본문 크기·간격·색상·배경은 이전 측정값과 비교해 유지됨을 확인했다.

## 시연용 기능

- **로그인:** 프런트엔드 데모 검증과 sessionStorage 세션이다. 실제 회원 인증이나 서버 권한 검증이 아니다. 기존 개발 설정은 존재하지만 그 비밀번호를 읽거나 출력하지 않았다.
- **가입/비밀번호:** 가입 입력 확인만 제공하며 실제 계정 생성·메일/SMS 인증·실제 비밀번호 변경은 하지 않는다.
- **장바구니·찜·회원정보·리뷰:** 브라우저 저장 방식이다. 실제 고객 서버와 동기화되지 않는다.
- **주문 확인:** 실제 주문서를 접수하는 기능이 아니라 선택 상품의 세션 내 미결제 확인이다. 배송지·연락처·카드 번호를 입력받지 않고 서버/결제사로 전송하지 않는다. `getOrders()`의 실제 주문 목록은 여전히 비어 있다.
- **주문/환불/배송 화면:** 기존 예시·디자인 미리보기 자료를 유지한다. 시연 확인에서 배송 조회로 이동해도 배송 요청이 없음을 표시한다.
- **리뷰:** 상품별 예시 리뷰와 해당 브라우저에서 작성한 데모 리뷰를 구분한다. 실제 구매 후기 서버가 아니다.
- **문의:** 사진과 문의는 해당 브라우저 IndexedDB에 저장된다. 운영자에게 발송되지 않는다.
- **AI:** 사이트 상품·FAQ·경로에 따른 자동응답이다. 실제 생성형 AI API나 상담사 연결이 아니다.

## 추가 연동 필요 / 이번에 만들지 않은 기능

1. 실서비스 인증·회원가입·이메일 중복 검사·SMS·비밀번호 변경 서버.
2. 실제 주문서와 주문 접수, 배송지/주문자 입력, 결제사·실결제·결제 완료/취소/환불, 운영 정책에 따른 배송비·쿠폰 할인·포인트 적용. 이번에는 개인정보를 받는 별도 주문서 폼을 만들지 않고 기존 주문 상세를 시연 확인으로 재사용했다.
3. 주문·택배사 실시간 배송 추적·회원 데이터의 서버 저장 및 계정별 권한 검증.
4. 실제 고객 리뷰/사진, 운영자 문의 수신·답변, 상품 Q&A 등록 및 AI API.
5. 최근 본 상품 사이드 메뉴는 기존 준비 중 안내다. 독립적인 기존 화면이 없어 가짜 경로를 추가하지 않았다.
6. 독립적인 이용약관·개인정보처리방침 페이지/운영 원문이 없다. 회원가입의 기존 약관 팝업은 디자인 시연용 예시이며 실제 운영 정책으로 대체 연결하지 않았다.
7. Instagram·YouTube·Kakao Talk 공식 계정이 없어 외부 주소를 만들지 않았다. 기존 이름·아이콘·마이페이지 화살표·제목 바를 유지하며, 삭제됐던 ‘연결 준비 중’ 문구를 다시 넣지 않았다.
8. STORE의 주소·영업시간·연락처는 예시다. 실제 매장 등록과 외부 지도 서비스의 길찾기 결과를 확인하지 않았다. 전화번호는 기존 텍스트 표시이고 매장 사진 4장은 준비 중이다.
9. 상품 전용 푸터의 별도 투명 토끼 원본은 여전히 없다. 전체 푸터 시안을 임의로 잘라 캐릭터로 사용하지 않았다.
10. 기존 완성 상세 3개의 본문에는 원래 찜 버튼이 없다. UI를 추가하지 않았으며, 해당 상품의 목록/검색/찜 기능은 유지한다.

## 최종 확인 및 테스트 한계

- PC 1920px, 태블릿 834px, 모바일 402/360px: Chrome 뷰포트 에뮬레이션으로 점검했다. 모바일 회원 메뉴·햄버거·AI는 실제 터치 입력 이벤트도 실행했다.
- 원본 상세 3개는 크기·간격·색상·배경을 비교했다. 현재 디자인을 새로 구성하거나 CSS를 변경하지 않았다.
- `npm.cmd run build`: 성공. 기존 큰 번들 경고가 남아 있다.
- `npm.cmd run lint`: 종료 코드 0. 기존 미사용 변수·Fast Refresh·effect 관련 경고는 남아 있으므로 경고 0 상태는 아니다.
- 실제 iOS/Android 장치, Safari/Firefox, 배포 호스팅의 새로고침 rewrite 설정은 테스트하지 않았다. 실결제·실제 고객 계정·SMS/메일 발송·SNS·택배사·AI 외부 API는 서비스가 없으므로 테스트하지 않았다.
- 모든 화면 표시와 지정한 주요 흐름을 검증했으나 모든 입력 조합 및 모든 쿠폰/공지/반품 버튼을 전수 클릭한 것은 아니다. 실행하지 않은 기능을 정상이라고 단정하지 않는다.
- 기존 테스트의 구형 선택자·문자열 이스케이프·새로고침 대기 부족은 점검 스크립트에서 수정해 재검증했다. 이를 사이트 결함으로 오인해 디자인을 변경하지 않았다.
- 테스트는 분리된 localhost:5188/5187에서 수행했고 저장 자료는 각 테스트의 복원 절차로 되돌렸다. 실제 비밀번호나 민감한 개인정보를 테스트 데이터로 사용하지 않았다.
- 불필요한 기존 파일 삭제, Git commit, Git push는 하지 않았다.
